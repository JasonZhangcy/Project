# 码道 CodeArts 用户规模增长（一）：大盘判断与友商打法拆解

> 撰写时间：2026-09
> 数据来源：公开报道、友商官方文档与帮助中心、券商研究报告、第三方榜单（AICPB / 易观 / QuestMobile / IDC）。
> 说明：厂商自报数据（注册用户、访问量）口径不一，本文用于判断"量级与方向"，不用于精确对标。

---

## 一、先给三个结论

### 结论 1：2026 年这个赛道的"用户规模"，已经不在开发者池子里决胜

2026 年夏天发生了一件几乎所有头部厂商同时做的事——**把 AI 编程产品并入 AI 办公 / 通用 Agent 产品线**：

- 阿里 8 月初把三条产品线合并成**千问办公**，Qoder 同步升级为"智能体工作台"，提供**编程模式 + 通用模式**双入口；
- 腾讯把 QClaw 并入 **WorkBuddy**，WorkBuddy 覆盖"办公、开发、设计"三大场景；
- 字节 7 月 30 日把飞书产品团队并入豆包，8 月 24 日又把 **TRAE、扣子团队一并整合**，并拆出 TraeCode / TraeWork 双产品，**积分互通**；
- 百度把内部办公智能体并进**百度搭子**。

这不是巧合，是同一个算术题的答案：

| 人群 | 中国量级 | 说明 |
|---|---|---|
| 专业开发者 | ~1000 万级 | 天花板明确，且已被 Copilot / Cursor / 通义灵码 / Trae 反复洗过 |
| 鸿蒙注册开发者 | 1100 万+ | 华为独有池子（HDC 2026 数据） |
| 泛职场知识工作者 | 数亿级 | AI 办公桌面端当前 MAU 仅约 3000 万，第三方估算还有 **约 20 倍**空间 |

**用户规模的量级，是由"你把自己定义成服务谁"决定的，不是由裂变效率决定的。**
裂变、分享、积分这类机制是**效率杠杆**（通常带来 10%~30% 的增量），换不来数量级跃迁。真正换量级的只有四件事：**入口卡位、免费门槛、生态供给、独家刚需**。

这是码道规划要回答的**第一个决策题**：
- **路线 A（深耕）**：在开发者盘子里做到"鸿蒙 + 信创"的绝对垄断，目标是千万级开发者的高渗透；
- **路线 B（破圈）**：像千问办公 / WorkBuddy 一样做"通用模式"，把 Coding 能力当底座，去打泛职场用户，目标是亿级；
- **路线 C（双轨）**：Qoder 的做法——开发者入口保持锋利，同时用同一底座切一个通用入口，两个入口共享账号与积分池。

我的建议是 **C，但有严格的先后**：先把开发者侧的漏斗和生态补齐（因为码道目前的漏斗有明显失血点，见第三节），同时用极低成本试水一个"移动端 / 网页端轻量入口"验证泛用户需求，再决定是否重投。**理由是：破圈能力的底座（云端 Agent、任务异步化、技能市场、积分中台）和深耕能力的底座是同一套，先建底座不浪费。**

### 结论 2：友商的增长不是靠某一个"绝招"，而是六层叠加

没有任何一家是靠单点裂变起来的。把公开信息拆开，能稳定复现的是一个**六层结构**（详见第二节）：

```
L6 组织层   企业采购 → 员工个人账号 → 家庭/社交扩散（B2B2C）
L5 心智层   社区、线下、内容、年度报告、认证徽章
L4 供给层   技能市场 / 插件市场 / 开放平台（第三方帮你拉新）
L3 回路层   产品内的分享、邀请、作品传播（PLG 自循环）
L2 入口层   预装、应用市场、IM、云控制台、系统级助手
L1 准入层   免费额度、注册门槛、试用方式
```

**越往下越是"地基"，越往上越是"放大器"。地基漏水的时候，放大器只会把水漏得更快。**

### 结论 3：码道当前最大的问题不是"缺裂变能力"，而是漏斗前段有三处明显失血

详见第三节。简单说：**注册门槛重、免费额度不足以养成习惯、产品没有任何对外传播的出口**。这三件事修好之前，做邀请裂变的 ROI 会被严重低估——因为拉来的人留不住，等于给友商做了教育。

## 二、友商打法的六层拆解

### L1 准入层：免费额度不是"成本"，是"习惯养成的燃料"

这一层是目前码道和友商差距最直观的地方。

| 产品 | 免费策略 | 关键设计 |
|---|---|---|
| 通义灵码 | 个人版**完全免费、不限时长** | 用免费换基数和数据，商业化放在企业侧 |
| 文心快码 | 个人免费 + **Auto-Free 兜底**：高级模型额度用完后**自动切换免费模型**，专业版 150k tokens/h，旗舰版限时 500k tokens/h | "**永不中断**"——这是极其重要的设计 |
| 千问办公 | 注册送 2000 积分；**每日首次登录领积分**（免费 500 / 标准版 1000 / 高级版 2000）；付费用户经济版模型**无限畅用** | 把免费额度做成**日更的回访理由** |
| Trae | 免费基础版；邀请一次双方各 **500 通用积分**，积分 **31 天有效** | 额度有效期短 → 逼出高频使用 |
| CodeBuddy | Free 100 积分；新用户 250 积分；绑卡得 **7 天 Pro 试用 + 500 积分**；混元 Hy3 旗舰模型**限时两周全免费（新老用户都给）** | 用"限时旗舰模型免费"做脉冲式拉活 |
| GitHub Copilot | Copilot Free 层；**学生 / 教师 / 热门开源项目 maintainer 免费**（学生：无限补全 + 200 AI Credits/月） | 用身份认证做精准免费，成本可控 |
| Claude Code | **Guest Pass**：每个付费用户可生成 3 个访客链接，好友得 **1 周免费**；好友转化付费，推荐人得 $10~15 usage credits | 奖励发的是**额度不是现金**，把用户锁在生态内 |
| **码道 CodeArts** | 体验版免费：**500 万 Tokens / 月** | 用完即止，无兜底、无日常补给、无邀请补给 |

**这里有一个必须点出来的算术问题。**

在 agentic 编码场景下，一次中等复杂度的任务（Agent 读 15~25 个文件、5~8 轮工具调用、带 Codebase 检索）累计输入 token 在 **30 万~80 万**是常态。也就是说：

> 500 万 Tokens / 月 ≈ **每月约 8~15 次中等复杂度 Agent 任务** ≈ 每个工作日不到 0.5 次。

而习惯养成（把工具变成"肌肉记忆"）的经验阈值大致是**连续 3 周、每工作日 3 次以上的成功调用**。按这个标准，**码道的免费档在设计上就无法让一个新用户跨过习惯养成线**——新用户大概率在第 3~7 天撞到额度墙，然后回到 Trae / 通义灵码（那边免费且不中断）。

**这意味着：在修复免费档之前，任何投放和裂变带来的新增，都是在给友商做用户教育。** 这是我认为投入产出比最高的一个动作，且不需要写多少代码。

可选的修复形态（不必等同于"无限免费"）：
1. **兜底不中断**：学文心快码，高级模型额度耗尽后自动降级到一个便宜的自研/开源模型继续服务，只是变慢/变弱，**绝不弹"额度已用完"**；
2. **日更补给**：学千问办公，每日登录发放小额 token，把额度从"月池"改成"日流"，顺便得到一个天然的 DAU 回访钩子；
3. **行为换额度**：完成新手任务、提交一个 Skill、写一篇实践案例、邀请一位好友、通过一次认证——都可换额度（这条同时是 L3 和 L5 的入口）；
4. **身份免费**：学 Copilot，学生 / 教师 / 开源 maintainer / 华为认证持证者，凭身份拿高额度。华为有 ICT 学院和认证体系，这条的执行成本极低而信号极强。

### L2 入口层：谁离用户更近，谁的获客成本更低

这一层是大厂真正的杀器，也是码道被低估的资产所在。

- **千问办公**：上线 30 天 3000 万用户、**企业用户占比过半**。核心不是产品好 30 倍，是**钉钉把入口给了它**（网页版 / 桌面端 / 钉钉 PC 端内入口，任一端登录即算）。
- **WorkBuddy**：2026-03-09 公测，PC 端月访问量从 3 月 885 万到 6 月 **2097 万**，7 月 MAU **1115 万**。抓手包括：**连接器打通企业微信 / 微信**（可在 IM 里远程下发任务）、原生集成腾讯文档 / IMA 知识库 / 乐享，8 月 4 日**上架华为鸿蒙电脑应用市场**成为该平台首个桌面办公智能体。
- **百度搭子**：7 月 MAU 674 万，**环比增长 1063.79%**，靠的是百度文库 + 网盘的存量导流（库库 AI 全平台 MAU 已超 1 亿）。
- **CodeBuddy**：用户主力是**微信小程序开发者**——生态绑定即入口。
- **通义灵码**：企业用户"几乎全是阿里云客户"——云控制台即入口。
- **OpenClaw** 的案例最有意思：它本身只是个开源项目，但腾讯云 2026 年 2 月推出"Lighthouse 一键部署镜像"后，**上线首周轻量应用服务器新增申购中近 45% 选择了该镜像**。说明"**开源项目 + 一键上云**"本身就是一条极强的获客通道。

**对码道的启示**：华为的入口资产比腾讯阿里差吗？不差，只是没接上：

| 华为侧入口 | 现状 | 可做的事 |
|---|---|---|
| 鸿蒙开发者（1100 万注册） | 码道有 ArkTS 增训模型，但终端 BG 还有 DevEco Code / DevEco CLI | 理顺定位（见第三节），把码道做成鸿蒙开发者的云侧首选 |
| HarmonyOS 终端（HarmonyOS 6 已破 8000 万台） | 未触达 | 鸿蒙电脑应用市场上架（WorkBuddy 都上了）、MateBook 预置 |
| 华为云控制台 / 云商店 | 弱关联 | 云主机开箱即用、CodeArts 研发流水线内嵌 |
| 华为开发者空间（免费云主机 180 小时） | 已存在但与码道未打通 | **零安装即用**的最佳载体 |
| 华为认证 / ICT 学院（覆盖数千所高校） | 未与码道绑定 | 认证 + 课程 + 实验包，教师即渠道 |
| HDC / 花粉俱乐部 / 华为商城 | 未联动 | 购机赠会员、开发者大会发放高额度 |

### L3 回路层：产品内生的传播，这是用户提到的"裂变"所在的层

这一层的友商做法可以归成三类，**难度和威力递增**：

**（a）邀请裂变——最容易做，但天花板明确**

Trae 的规则可以直接当模板：
- 双向奖励：邀请人与被邀请人**各得 500 通用积分**；
- **封顶 3500 积分**（防刷 + 控成本）；
- 积分**31 天有效**（逼出使用）；
- 奖励是**通用积分，TraeCode / TraeWork 通用**（跨产品导流）；
- 认定规则极其清晰：必须是**此前从未注册过**的新账号，且**必须完成登录**才算有效。

Claude Code 的 Guest Pass 是更聪明的变体：**不直接发积分，而是发"1 周完整体验权"**，并且只在被邀请人**付费转化**后才给推荐人 $10~15 额度。这把奖励和商业价值对齐了，作弊几乎无利可图。

> **判断**：邀请裂变是标配，必须做，但要清醒——它的贡献量级通常是**新增的 10%~25%**，而且严重依赖 L1（如果产品留不住人，被邀请人拿完积分就走）。
> **建议的做法**：不要做成纯积分，做成**"Guest Pass + 阶梯积分"双轨**——邀请链接本身给对方一个 7 天专业版体验（降低对方决策成本），对方留存满 7 天且完成 N 次有效会话后，邀请人才拿大额奖励（对齐真实价值 + 天然防刷）。

**（b）作品传播——威力大一个量级，国内 AI 编程工具普遍没做透**

这是 Lovable 的核心引擎，也是它能做到 **6000 万+ 项目、9 亿+ 月访问、$13.3B 估值**的原因：

> **用户产出的东西本身就是广告，而且是可以被下一个用户直接接手继续用的广告。**

Lovable 的链路：生成应用 → 一键发布到公网 → 任何人可访问 → 访客可 **Remix（复刻并继续改）** → Remix 的人必须注册 → 新用户。它还在 2026 年给每个公开发布的应用**自动生成 trust center 页面**（展示 HTTPS、依赖检查、SBOM、部署可追溯等），把"作品可信"也做成了传播物料。

对比之下，国内 AI 编程工具的产出物**几乎全部锁在本地 IDE 里**，没有任何对外出口。这是一块明显的空地。

**（c）过程传播——几乎无人做，但适配中文互联网的内容生态**

AI Coding 最有传播力的内容其实不是结果，是**过程**：Agent 如何理解需求 → 如何规划 → 改了哪些文件 → 测试如何通过。技术博主在 B站/掘金/知乎/小红书自发生产的就是这类内容。但目前所有工具都要求用户**手动录屏、手动剪辑、手动写文章**。

**把这件事产品化（一键把一次 Agent 会话导出成可交互分享页 / 竖屏短视频），等于给几万个技术内容创作者发了免费的生产工具，而每一份产出都带你的水印。**

### L4 供给层：让第三方替你拉新

这一层决定**长期天花板**，是目前差距最大、也最值得投入的地方。

| 产品 | 生态体量 | 机制设计 |
|---|---|---|
| WorkBuddy | **技能市场 8 万+ 技能**，覆盖 100+ 领域专家模板；开放平台 open.workbuddy.cn 首批百家生态伙伴、9 款联名智能硬件、20+ 行业应用 | 技能即"专家"，非技术用户直接调用 |
| Qoder | **40+ 连接器、70+ 插件、20K+ 技能**；接入 MCP / ACP | 打通代码仓、项目管理、云服务、内部工具 |
| Claude Code | 官方市场 172 个插件、社区 500+ 插件、270+ 内置 Skills；**任何 GitHub 仓库只要根目录有 `.claude-plugin/marketplace.json` 就是一个市场** | **去中心化分发**——这是最关键的设计 |
| 华为 DevEco（终端 BG） | 把 **2000 多万字**鸿蒙官方文档转成可被 Agent 调用的知识资源，并开放给第三方主流编程 Agent | 内容资产是真护城河 |
| **码道 CodeArts** | 有 Skills / Rules / MCP / 智能体中心（基础版以上） | 但**缺少开放提交、去中心化分发、创作者激励** |

Claude Code 的设计里有两个点值得直接抄：
1. **去中心化市场**：不做审核制的中心化商店（那会成为增长瓶颈），而是"任何 Git 仓库都能当市场"。分发成本为零，供给增长不受官方运营人力限制。
2. **安装前可见成本**：安装界面会显示这个插件**每轮会往上下文里加多少 token**，以及它会装入哪些命令/agents/skills/hooks/MCP。这是建立信任的关键细节。

而**所有友商都还没做的一件事**是：**给技能创作者分成**。目前的技能市场都是"用爱发电 + 官方运营"。如果码道把"Skill 被调用产生的 token 消耗，按比例分给作者"做成机制，就把生态从"兴趣供给"升级成"职业供给"——这会引来专业团队，而专业团队自带流量。

### L5 心智层：社区、线下、内容、认证

Trae 是这方面做得最重的：**2025 年足迹覆盖全球 60 多个城市，130 多场官方黑客松 / Meetup / TRAE Friends / TRAE on Campus 活动，线下触达 2 万余名开发者**；同时有 TRAE Fellow / TRAE Expert 的 KOL 体系（社区 KOL 去高校做分享）。
它还有两个轻量但有效的动作：
- **SOLO 邀请码稀缺营销**：2.0 发布时 SOLO 采用邀请制，一度在闲鱼被炒到几百块。这制造了强烈的"拿到即优越"的传播；
- **年度产品报告**：公布"6000 万个会话、5 亿条 Query、用户平均周活跃天数近 5 天、Cue 累计推荐近 10 亿次代码、采纳率提升超 80%"——这既是 PR 素材，也给每个用户一个"我是这 600 万之一"的归属感。

Qoder 的心智打法是另一路：**创始人访谈 + 第三方权威背书**（IDC 市场份额第一、Gartner 魔力象限唯一中国公司）。

**对码道的启示**：华为在"认证"这件事上有一个别人复制不了的体系——**华为认证（HCIA/HCIP/HCIE）每年数十万考生，且在国内企业招聘中有实际含金量。** 把"AI 编程工程师（基于码道）"做成一个正式认证方向，意味着：
- 考生必须使用码道完成实操 → 强制激活；
- 认证有含金量 → 用户主动来，获客成本趋近于零；
- 高校 ICT 学院可以开课 → 教师变成渠道；
- 证书可在简历/招聘平台展示 → 品牌外溢。

这是我认为**华为资产里被低估最严重的一条**。

### L6 组织层：B2B2C，企业渗透反哺个人规模

千问办公上线首月 3000 万用户中**企业用户占比过半**，靠的是钉钉 + 阿里云的企业渠道交叉销售。WorkBuddy 6 月起把腾讯文档、IMA、乐享、企微全开放给它，企业版提供 SSO、用量管控、集中计费、私有化部署（符合等保 2.0）。

这条路径对华为云是**最顺的**——华为云的政企客户基本盘、信创合规能力、私有化部署经验，都是现成的。关键是要把链路补完：

> 企业采购席位 → 员工在公司用 → **员工用个人账号也能在家/在个人项目用（个人版权益自动赠送）** → 员工离职/换公司把习惯带走 → 新公司采购

目前多数厂商的企业版和个人版是割裂的。**把"企业席位自动附赠员工个人版权益"做成机制，是一个成本极低、但能把 B 端席位数直接放大成 C 端 MAU 的杠杆。**

## 三、码道当前的位置：对标体检

### 3.1 码道已有的牌（不弱）

- **全形态覆盖**：AI IDE、VS Code 插件、JetBrains 插件、CLI/TUI —— 形态齐全度对齐 Qoder；
- **工程化能力**：Codebase 代码库索引、知识空间、规范驱动开发、Agent Space（多会话并行 / 多 Agent 并发）、Skills / Rules / MCP；
- **独家模型**：GLM-4.7-ArkTS-SPARK（基于 GLM 增训鸿蒙代码与开发知识）—— **这是别人没有的**；
- **独家内容**：华为多年研发实践、千亿级代码库沉淀、企业级开发标准；
- **独家场景**：鸿蒙、鲲鹏、昇腾、openEuler 的迁移与适配；
- **企业能力**：审计日志、模型管理、企业自定义模型、用量管理、安全隔离代码仓、IP 白名单、SSO。

### 3.2 三处明显失血点

**失血点 1：免费额度不足以跨过习惯养成线**（已在 L1 详述）
体验版 500 万 tokens/月 ≈ 每工作日不到 0.5 次中等 Agent 任务；无兜底、无日更、无行为补给。友商侧是"免费不中断"（文心快码）、"每日送"（千问办公）、"邀请送"（Trae）。
**这是当前 ROI 最高的修复项。**

**失血点 2：注册与登录门槛重**
码道要求登录华为云账号。华为云账号注册流程相对重（企业级云账号体系、实名要求），而友商侧普遍支持手机号/微信/GitHub 一键登录，Claude Code 甚至提供**完全不需要注册的 Guest Pass 体验**。
对于一个"想花 3 分钟试试"的开发者，账号环节的流失可能是整个漏斗里最大的一段。
**建议**：做"**先用后注册**"——网页版/插件首次使用给 N 次免登录额度，产生价值后再引导注册；同时接入华为账号（终端侧，鸿蒙用户已有）而不只是华为云账号。

**失血点 3：产品完全没有对外传播出口**
码道目前所有价值都封闭在 IDE 内。没有作品分享、没有会话分享、没有 Skill 分享链接、没有战绩/报告、没有社区广场。
**这意味着码道的增长目前 100% 依赖付费投放和渠道推广，自然增长系数（K 因子）接近 0。**

### 3.3 一个必须内部拉齐的问题：码道 vs DevEco Code

HDC 2026 上，华为终端 BG 发布了 **DevEco Code**（基于华为毕方和 OpenCode 构建的"懂鸿蒙"的编程智能体）和 **DevEco CLI**（面向编程 Agent 的鸿蒙开发命令行工具，且**支持市面主流编程 Agent**，并把 2000 多万字鸿蒙官方文档转成 Agent 可调用的知识资源）。

而码道（华为云）也在主打鸿蒙增训模型和 ArkTS 支持。

**如果两者定位不清，鸿蒙这 1100 万开发者的池子会在内部被稀释掉，这是最可惜的。** 建议的切分逻辑（供讨论）：

| 维度 | DevEco Code（终端 BG） | 码道 CodeArts（华为云） |
|---|---|---|
| 定位 | 鸿蒙应用开发的**本地原生工具链** | **跨技术栈的云侧研发智能体平台** |
| 场景 | 端侧应用、ArkTS、多设备适配 | 企业级工程、后端服务、迁移改造、云上协同、CI/团队治理 |
| 协同方式 | 码道**调用 DevEco CLI**（它本来就"支持市面主流编程 Agent"）+ 复用那 2000 万字知识资源 | 码道成为"最懂鸿蒙的通用编程 Agent" |

**能拿到的最大收益是：码道不需要重复造鸿蒙知识，直接接 DevEco CLI 和官方知识库，就能对 1100 万鸿蒙开发者说"你用码道，鸿蒙这块和官方工具是一套"。** 这比自己再增训一版模型的杠杆大得多。

## 四、从友商身上能提炼的 8 条通用规律

1. **免费的目的不是省钱，是让用户跨过习惯养成线。** 额度设计要保证"连续 3 周、每日 3 次以上成功调用"，宁可降级也**不要中断**。
2. **奖励发额度，不发现金。** Claude Code、Trae、千问办公一致——发额度把用户锁回生态内消费，还顺带提升活跃。
3. **积分要跨产品通用。** Trae 的"通用积分 TraeCode/TraeWork 通用"就是在用一个产品的用户去激活另一个产品。
4. **积分要有有效期。** Trae 的 31 天、千问办公的 3 个月——有效期把"存量额度"转化成"使用压力"。
5. **入口比产品力先生效。** 千问办公首月 3000 万靠钉钉，百度搭子环比 1063% 靠文库网盘，CodeBuddy 靠微信小程序生态。
6. **供给侧生态是长期天花板，去中心化分发是关键。** Claude Code 的"任何 Git 仓库都是市场"让供给增长不受官方人力限制。
7. **用户产出的东西必须能被别人看见、能被别人接手。** Lovable 的 Remix 是 AI 编程领域被验证的最强增长回路。
8. **线下与社区不是"品牌预算"，是留存手段。** Trae 130 场线下活动对应的是"用户平均周活跃天数近 5 天"。
