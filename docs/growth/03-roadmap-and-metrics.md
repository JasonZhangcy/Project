# 码道 CodeArts 用户规模增长（三）：优先级、路线与指标

## 一、优先级判断框架

用 **ICE** 打分（Impact 影响 × Confidence 确信度 × Ease 易实现度，各 1~5 分，分数 = I × C × E，满分 125）。
这里的 Impact 特指"**对用户规模的影响**"，不是对收入的影响。

### 1.1 第一梯队（分数 ≥ 60，建议立刻启动）

| # | 能力 | I | C | E | 分 | 关键理由 |
|---|---|---|---|---|---|---|
| A3 | 免费额度兜底不中断（Auto-Free） | 5 | 5 | 4 | **100** | 修复最大失血点；文心快码已验证；工程量小 |
| A4 | 额度日更（每日登录发放） | 4 | 5 | 5 | **100** | 千问办公已验证；同时造出 DAU 钩子 |
| A1 | 免登录试用 Guest Mode | 5 | 4 | 4 | **80** | 账号环节大概率是最大单段流失 |
| A2 | 轻量登录（华为账号/手机号/微信/Gitee） | 4 | 5 | 4 | **80** | 与 A1 配套，缺一不可 |
| D1 | 邀请裂变基础版 | 3 | 5 | 5 | **75** | 标配，Trae 规则可直接复用 |
| B1 | 仓库体检报告（零 prompt 展示价值） | 4 | 4 | 4 | **64** | Qoder Repo Wiki 已验证；激活率抓手 |

## 二、分阶段路线

> 不按日历排期，按**依赖关系**排序。每个阶段有明确的"进入下一阶段的判据"。

### 阶段一：止血（修漏斗）

**做什么**
1. A3 免费额度兜底不中断
2. A4 额度日更 + A5 任务中心
3. A1 免登录试用 + A2 轻量登录
4. B1 仓库体检报告（零 prompt 首次价值）
5. H1 积分中台 + H2 归因 + H5 漏斗埋点（**这三条必须和上面并行，否则后面全是黑盒**）

**为什么先做这些**
当前每投放一个新用户，大概率在"注册"和"额度耗尽"两处流失。在 K 因子接近 0、漏斗漏水的状态下做裂变，等于放大浪费。

**进入下一阶段的判据**
- 新用户首次会话完成率 > 70%
- 7 日留存 > 30%
- "额度耗尽导致的会话中断"事件下降 80% 以上

### 阶段二：起环（造增长回路）

**做什么**
1. D1 邀请裂变基础版 → D2 升级为 Guest Pass + 延迟奖励
2. D6 Skill 深链分享 + D8 排行榜 + C3 个人报告
3. E1 去中心化 Skill 市场开放提交
4. A6 身份免费计划（学生/教师/OSS/认证）
5. A8 竞品迁移助手
6. C2 云端异步任务 + 跨端推送
7. F1 鸿蒙入口打通（接 DevEco CLI + 2000 万字官方知识资源）

**为什么是这个顺序**
D 类（传播）需要 H1/H2/H3 就位；E1（供给）需要有足够用户基数才有创作者愿意投入；F1 需要跨部门对齐，提前启动。

**进入下一阶段的判据**
- K 因子（每个用户带来的新用户数）> 0.15
- 第三方提交的 Skill 数 > 500，且有 ≥ 20% 被至少 10 人安装
- 鸿蒙场景用户占比 > 15%

### 阶段三：放大（换量级）

**做什么**
1. F2 Android → 鸿蒙迁移 Agent（先窄场景 PoC，验证成功率后再放大）
2. D3 作品广场 + Remix（并与鸿蒙元服务/应用市场打通上架链路）
3. E2 创作者分成
4. F5 华为认证 AI 编程方向 + F6 高校课程包
5. F7 终端侧入口（鸿蒙电脑应用市场 / MateBook 预置）
6. G1/G2 通用模式与移动端轻量入口（依赖 01 篇结论 1 的路线决策）

## 三、指标体系

### 3.1 北极星指标的选择

**不要用"注册用户数"当北极星。** 友商公布的"600 万""3000 万"都是注册口径，而 Trae 自己的数据显示注册 600 万对应 MAU 只有 160 万（约 27%）。注册数容易被活动灌水，且无法指导产品决策。

建议北极星：**周活跃编码用户数（WAU-Coding）**
定义：一周内至少完成 **3 次有效 Agent 会话**（有效 = 产生了代码变更或被用户采纳的输出）的独立用户数。

理由：
- "有效会话"排除了领积分即走的羊毛用户；
- "3 次"对应习惯养成的最小信号；
- 这个指标涨，收入和口碑一定跟着涨。

### 3.2 分层指标

| 层 | 指标 | 说明 |
|---|---|---|
| **获取** | 新增注册、**新增激活**（完成首次有效会话）、渠道 CAC、K 因子 | K 因子 = 邀请带来的新增 / 总新增 |
| **激活** | 首次会话完成率、首次成功率、下载→首次成功的中位时长 | 目标：中位时长 < 10 分钟 |
| **留存** | 次日/7日/30日留存、**周均活跃天数** | 对标 Trae 公布的"周均近 5 天"、国际版付费用户超 6 天 |
| **深度** | 人均周会话数、人均周 token、Skill 安装数、MCP 接入数、Agent Space 并发使用率 | 深度是留存的先行指标 |
| **传播** | 分享次数、分享页 UV、Remix 次数、邀请发起率、邀请转化率 | 分享页 UV 要单独看 SEO 来源 |
| **生态** | 第三方 Skill 数、活跃创作者数、Skill 安装 CR、市场来源新增用户 | 生态健康 = 供给数 × 被使用率 |
| **组织** | 企业席位数、席位激活率、**企业员工个人账号转化率** | 最后一项是 B2B2C 的核心指标，目前行业普遍不看 |

### 3.3 必须单独埋点的三个"断崖点"

1. **账号断崖**：点击登录 → 完成登录的转化率，以及在哪一步放弃（验证码 / 实名 / 企业信息）
2. **额度断崖**：用户第一次撞到额度限制的时间点，以及撞到之后 24 小时内的回访率
3. **首次失败断崖**：首次 Agent 任务失败的用户，7 日留存比成功用户低多少

> **这三个数据拿到之前，任何增长投入都是在拍脑袋。**

## 四、裂变机制的具体设计建议

综合 Trae、Claude Code、千问办公的规则，给一版可直接讨论的设计：

### 4.1 邀请裂变

| 项 | 建议 | 依据 |
|---|---|---|
| 奖励对象 | 双向 | Trae：双方各 500 积分 |
| 奖励形式 | **额度/积分，不发现金** | Claude Code 发 usage credits 而非现金，把用户锁回生态 |
| 被邀请人奖励 | 立即发放 + **7 天专业版体验权** | Guest Pass 比积分更能降低决策门槛 |
| 邀请人奖励 | **延迟发放**：被邀请人注册后给小额，被邀请人 7 日内完成 ≥ 5 次有效会话再给大额 | 对齐真实价值，天然防刷 |
| 阶梯 | 3 / 5 / 10 / 20 人解锁递增权益（额度 → 高级模型权限 → 实物/认证券） | 阶梯比线性更能激发中长尾 |
| 封顶 | 单人活动期封顶（Trae 是 3500 积分） | 控成本 + 防职业羊毛 |
| 有效期 | 奖励积分 31 天有效 | Trae 同款，逼出使用 |
| 新用户认定 | **此前从未注册过**且**完成登录并产生首次有效会话** | Trae 只要求登录，建议加严到"首次有效会话" |
| 规则公示 | 活动页明确写清：时间、资格、流程、奖励档位、发放时间、无效数据处理 | 社区实践的共识：规则不清是纠纷主因 |
| 反馈 | **实时可查的进度页 + 排行榜** | 社区实践："用户花时间邀请别人，若始终不知道是否成功，动力很快耗尽" |

### 4.2 分享激励（注意：分享和邀请是两件事）

分享的目标**不是拉新数，是内容曝光量**。所以奖励应该挂在**曝光**上，而不是挂在分享动作上：

- 分享动作本身：给极小额度（防止为了积分刷分享）
- 分享页 **UV 达到阈值**：给阶梯奖励（100 UV / 500 UV / 2000 UV）
- 分享页带来**注册转化**：给大额奖励
- 作品被 **Remix**：给最大额奖励（因为 Remix 一定带来注册）

> 这样设计的好处：用户会自发去优化自己分享内容的质量和渠道，而不是机械地点"分享"。

## 五、风险与红线

| 风险 | 说明 | 应对 |
|---|---|---|
| **刷量与羊毛** | 积分类活动必然引来职业工作室 | 奖励后置 + 设备指纹 + 行为序列检测 + 单账号封顶 + 规则明示"一人一号，否则全部无效" |
| **免费成本失控** | Agent 场景 token 消耗远高于补全场景 | 分级算力（简单任务走小模型）+ 兜底模型必须是低成本模型 + 单用户 QPS/日调用动态上限（千问办公的"前期宽松、后期动态调整"是可参考的公开做法） |
| **用户结构劣化** | 拉来大量羊毛用户，WAU 好看但付费转化和口碑下降 | 北极星用"有效会话"口径；分渠道看留存，及时关停劣质渠道 |
| **内部左右手互搏** | 码道 vs DevEco Code 在鸿蒙场景重叠 | 尽早拉齐定位，改"竞争"为"码道调用 DevEco CLI"的协同（见 01 篇 3.3） |
| **安全与合规** | Agent 本地权限、代码上传、生成内容安全 | 2026 年 3 月 CNCERT 已就开源 AI 智能体发布国家级风险提示；本地权限类能力必须前置合规评审。反向利用：把"安全"做成对政企的卖点（参考 Replit Security Scan、Lovable 自动 trust center） |
| **作品广场的内容风险** | 用户公开发布的应用可能含违规内容或泄露密钥 | 自动密钥扫描（2025 年曾有 1700+ Lovable 应用暴露 API key 的公开案例）、内容审核、默认私有 |
| **数据口径虚高的诱惑** | 对外可以报注册数，对内绝不能用 | 内部决策一律用 WAU-Coding |

## 六、给决策层的一页纸

**问题**：码道要拓展用户规模，从哪下手？

**判断**：
1. 当前不是"缺增长玩法"，是**漏斗前段在失血**——免费额度（500 万 tokens/月）不足以让新用户跨过习惯养成线，注册门槛偏重，且产品没有任何对外传播出口（K 因子≈0）。
2. 邀请裂变、分享得积分这类机制**必须做但只是效率杠杆**，量级贡献在 10%~30%，不改变数量级。
3. 真正能改变数量级的只有四件事：**入口卡位、免费门槛、生态供给、独家刚需**。华为在这四件事上**都有牌，但都没打**。

**建议的三个下注**：
1. **止血**：免费额度兜底不中断 + 免登录试用 + 零 prompt 的仓库体检报告。工程量小，确定性最高。
2. **独家**：把鸿蒙 1100 万开发者当作主战场——接 DevEco CLI 和官方 2000 万字知识资源，把"Android → 鸿蒙一键迁移"做成爆款单点，并与华为认证体系绑定。**这三条友商抄不走。**
3. **生态**：开放的、去中心化的 Skill 市场 + **创作者分成**。分成机制是全行业空白，谁先做谁虹吸优质供给。

**需要决策层拍板的三件事**：
1. 路线选择：深耕开发者 / 破圈泛用户 / 双轨（建议双轨但有先后）
2. 免费额度的成本上限：愿意为"习惯养成"付多少 token 成本
3. 码道与 DevEco Code 的定位切分，以及与终端 BG、ICT 学院、认证体系的协同机制
